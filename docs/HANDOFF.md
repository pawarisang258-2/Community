# HANDOFF — Community Voice Dashboard สำหรับ Antigravity

**สถานะ:** ส่งต่อเพื่อปรับปรุง UI/UX โดยรักษาข้อมูลและตรรกะของ Dashboard Final  
**ต้นฉบับที่ต้องใช้:** `community_voice_tab2_two_large_charts(1).html` → `index.html`  
**ห้ามเริ่มเขียนใหม่จากศูนย์**  
**เอกสารข้อกำหนด:** `docs/BRD.md`

## 1. เป้าหมายงานที่ส่งต่อ

ปรับ Dashboard Final ให้เป็นเว็บไซต์ Data Storytelling ที่มีสีสัน น่าใช้งาน มีภาพประกอบและปฏิสัมพันธ์แบบสนุก แต่ยังคงคุณภาพเชิงวิชาการ โดยเฉพาะแหล่งข้อมูลใต้ทุกกราฟ ตาราง และ KPI และไม่ทำลายฟังก์ชันเดิม

## 2. สภาพปัจจุบันของโค้ด

- เป็น standalone HTML รวม CSS, JavaScript, Plotly และข้อมูลฝังอยู่ในไฟล์เดียว
- มี 3 แท็บ: ภาพรวมประเทศ / เจาะลึกจังหวัด / การเปลี่ยนแปลงและนโยบาย
- แท็บ 1: KPI, Thailand Choropleth, Treemap, Region × Issue Heatmap
- แท็บ 2: KPI เฉพาะจังหวัด, กราฟปัญหา Top 3, กราฟเทียบมัธยฐานจังหวัดที่รายงานปัญหาเดียวกัน, Evidence Explorer, Similar Provinces, Co-occurrence Matrix, Audit Table
- แท็บ 3: Persistence Matrix, Dumbbell Chart, Province Tile Grid, Policy Explorer
- ไฟล์ CSV ใน Repository: `data_clean_grouped_region.csv` และ `group1_...csv` ถึง `group9_...csv` (อาจยังอยู่ root)
- **อย่าคิดว่า CSV ใน Repository ถูกอ่านอัตโนมัติ** เพราะ HTML เวอร์ชันปัจจุบันฝังข้อมูลอยู่ ต้องตรวจและวางแผนแยกไฟล์อย่างระมัดระวัง

## 3. สิ่งที่ต้องทำตามลำดับ (ทำทีละขั้นและ Commit)

### Phase 0 — สำรวจโดยไม่แก้โค้ด
1. ตรวจไฟล์จริงและ DOM IDs / ฟังก์ชัน Plotly / event handlers / filter state
2. ตรวจจำนวนข้อมูลหลักและข้อมูลประกอบที่ฝังอยู่ เทียบกับ CSV ที่มีใน Repository
3. สร้าง `docs/PROJECT_STATUS.md` บันทึกสถานะ ปัญหาที่พบ และสิ่งที่จะทำ
4. สำรอง `index.html` ไว้ใน `backup/` ก่อนแก้
5. ตรวจ path GitHub Pages และชื่อไฟล์ให้เป็น `index.html` **ไม่ใช่** `index.html.html`

### Phase 1 — ระบบแหล่งที่มา (สำคัญสูงสุด)
1. สร้าง metadata กลางสำหรับทุกชุดข้อมูล เช่น `source_name`, `agency`, `source_url`, `years`, `unit`, `calculation`, `validation_status`, `limitations`
2. ผูก metadata กับ chart/table/KPI แต่ละตัว (ห้ามใช้ footer เหมือนกันหมดหากใช้ข้อมูลต่างชุด)
3. Render `<footer>` หรือแถบ Source Footer ใต้ทุก visualization รวมถึง drilldown/modal และตาราง
4. กราฟที่ใช้ข้อมูลหลักแสดงลิงก์ตรง: `https://data.go.th/dataset/0602_00_0002`
5. กราฟที่ใช้ CSV ประกอบแสดงชื่อไฟล์และสถานะ `รอยืนยันค่ากับแหล่งต้นทาง` จนกว่าจะมี URL ระดับชุดข้อมูล/ตารางที่ตรวจสอบได้
6. หากกราฟรวมหลายแหล่ง ให้แสดงทุกแหล่งและอธิบายว่าแต่ละแหล่งใช้ทำอะไร
7. เพิ่มไอคอน `ⓘ วิธีคำนวณ` ให้ผู้ใช้กดดูนิยาม หน่วย ตัวหาร และข้อจำกัด

**ตัวอย่าง source footer:**

> แหล่งข้อมูล: สำนักงานสถิติแห่งชาติ — ความต้องการให้รัฐบาลช่วยเหลือประชาชนในหมู่บ้าน/ชุมชน 3 อันดับแรก ([data.go.th](https://data.go.th/dataset/0602_00_0002)) · ปี 2567 · หน่วย: ร้อยละหมู่บ้าน/ชุมชน · วิธีคำนวณ: แสดงค่า `Per_vill` ของปัญหาที่ติด Top 3 ในจังหวัดที่เลือก · หมายเหตุ: อันดับเสมออาจมีมากกว่า 3 รายการ

**ตัวอย่างสำหรับตัวชี้วัดที่ยังไม่ยืนยัน:**

> แหล่งข้อมูลที่ใช้ใน Dashboard: `group2_cost_of_living_cpi_77prov.csv` · ปี 2567 · หน่วย: ดัชนี CPI · สถานะ: ยังไม่ยืนยันค่ารายจังหวัดกับตารางต้นฉบับ · ข้อจำกัด: ไม่ใช้ระดับดัชนีเพื่อสรุปว่าจังหวัดหนึ่งมีค่าครองชีพสูงกว่าอีกจังหวัดโดยตรง

### Phase 2 — ดีไซน์ใหม่อย่างระมัดระวัง

**Theme: “Voices of Thailand” — สีสันร่วมสมัย เหมาะกับเรื่องเสียงของชุมชน**

- พื้นหลัง: off-white `#FAF8FF` / pale cream `#FFF9F0`
- สีตัวอักษร: deep navy `#24234B`
- Primary: purple `#7655D6`
- Accent: coral orange `#FF8248`, mint green `#22C995`, sky blue `#58B7E8`, soft pink `#F5A3C3`
- Cards: ขาว ขอบบาง เงาเบา มุมโค้ง 16–22px
- Header: ภาพประกอบเมืองและชุมชนหลายพื้นที่ + speech bubbles / เส้นคลื่นเสียงแบบ abstract, ไม่ใช้ภาพถ่ายจริงที่ไม่มีสิทธิ์
- ไอคอน: map-pin, chart, megaphone, people, information, headphones/speaker; ใช้ชุดไอคอนเดียวกัน
- เพิ่ม micro-animation แบบ subtle เฉพาะการเปลี่ยนแท็บ/ตัวกรอง/เปิดข้อมูล; ห้ามทำให้หน้าจอกระพริบหรือข้อมูลเคลื่อนไหวจนอ่านยาก
- ภาพประกอบใช้ SVG ที่สร้างเองได้ หรือรูปที่มีสิทธิ์ใช้พร้อมเครดิตและ alt text
- หลีกเลี่ยงธีม Halloween / สีดำหนัก / ปุ่มลอยที่บังกราฟ แม้ใช้ความสนุกแบบ Dashboard ของเพื่อนเป็นแรงบันดาลใจ

**สัดส่วนกราฟ:**
- Desktop: กราฟหลัก 2 ใบที่ขนาดสมดุล; หากชื่อแกนยาวให้ใช้แถวละกราฟแทนโดยคงความสูงพอดี ไม่ยืดเป็นพื้นที่ว่างใหญ่
- Plotly ใช้ `responsive: true`, `autosize`, `ResizeObserver` หรือ `Plotly.Plots.resize` เมื่อเปลี่ยนแท็บ/ขนาดหน้าต่าง
- ให้ margin ซ้ายพอสำหรับชื่อปัญหาจริง ไม่แสดงแค่ `อันดับ 1 · 1` หากทำให้ไม่รู้ว่าปัญหาอะไร
- กราฟย่อยทุกใบมี min-height พอดี, label ไม่ทับ legend/modebar, ไม่ใช้ x-axis 0–100 สำหรับค่าที่ไม่ใช่ร้อยละ
- Mobile: 1 คอลัมน์, tooltip และแถบแหล่งที่มายังอ่านได้

### Phase 3 — ลูกเล่นที่ใช้งานได้จริง

1. **Sound Toggle:** ปุ่ม `🔊 เปิดเสียง / 🔇 ปิดเสียง` อยู่ใน header; ค่าเริ่มต้น **ปิด**; เก็บสถานะระหว่างแท็บภายใน session
2. เมื่อผู้ใช้เปิดเสียงแล้ว คลิกแท็บ/เลือกจังหวัด/กดดูข้อมูล สามารถเล่นเสียงสั้น ๆ เบา ๆ (Web Audio API หรือไฟล์เสียงที่มีสิทธิ์ใช้); **ห้าม autoplay** และต้องเคารพการตั้งค่า accessibility
3. คลิกจังหวัดบนแผนที่ → เปิดแท็บ 2 และเลือกจังหวัดนั้น
4. คลิก heatmap/treemap/co-occurrence → เปิดรายละเอียดที่ตรงกับค่าที่กด ไม่เด้งไปจังหวัดผิด
5. ปุ่ม `ล้างตัวกรอง`, `กลับไปภาพรวม`, breadcrumb, ปุ่ม `ⓘ แหล่งข้อมูล` และ tooltip ช่วยเหลือ
6. ปุ่ม `บันทึกภาพกราฟ` หรือ `ดาวน์โหลด CSV เฉพาะข้อมูลที่แสดง` (ถ้าเพิ่มได้โดยไม่กระทบความถูกต้อง)
7. ปุ่มทุกตัวต้องมี action จริง; ห้ามเพิ่มปุ่มตกแต่งที่กดแล้วไม่เกิดอะไร

### Phase 4 — ตรวจข้อมูลและทดสอบ

- ห้ามสร้าง mock data หรือเติมค่าที่ไม่มีต้นฉบับ
- ห้ามเปลี่ยน `Per_vill` ให้เป็นคะแนนสะสมหรือรวมข้ามปัญหา
- ห้ามนับแถวแทนจำนวนจังหวัดไม่ซ้ำ
- อันดับเสมอ: รักษาทุกรายการที่มีอันดับ Top 3 ตามข้อมูลจริง
- แยก `source_verified` กับ `value_verified` ใน metadata เพราะรู้ชื่อหน่วยงานไม่เท่ากับยืนยันตัวเลข
- ข้อมูลตัวชี้วัดประกอบ 9 กลุ่ม **ยังไม่ผ่านการยืนยันค่ากับตารางต้นทางครบทุกไฟล์**; ต้องไม่แสดง badge “ตรวจสอบผ่าน” แบบเหมารวม
- ตรวจ filter ปี 2566/2567, จังหวัด, ภาค, กลุ่มปัญหา และ interaction ทั้งสามแท็บ
- ตรวจไม่มี console errors, ไม่มีกราฟว่างผิดปกติ, ไม่มีตัวเลขทับ, ไม่มีปุ่มเสียงเล่นเอง
- ตรวจ Source Footer ทุกองค์ประกอบด้วย checklist
- ตรวจการทำงานบน Chrome desktop, mobile viewport, และ GitHub Pages

| Dumbbell Chart | CSV ข้อมูลหลัก | จำนวนจังหวัดไม่ซ้ำใน Top 3 ของปี 2566 เทียบ 2567 |

## 6. Definition of Done

- [ ] ทุกแท็บและการคลิกทำงานเหมือนเดิมหรือดีขึ้น
- [ ] Source Footer ครบทุกกราฟ KPI ตาราง และรายละเอียดที่เปิดจากการคลิก
- [ ] ไม่มีแหล่งที่มา URL ปลอม หรือสถานะยืนยันข้อมูลเกินหลักฐาน
- [ ] ดีไซน์สีสัน ภาพประกอบ และเสียงแบบ opt-in พร้อม accessibility
- [ ] กราฟสมส่วน ไม่ล้น ไม่ทับกันทั้ง desktop และ mobile
- [ ] ไม่มีการแก้สูตร/แถวข้อมูลต้นฉบับโดยพลการ
- [ ] เปิดผ่าน GitHub Pages ได้
- [ ] README, DATA_DICTIONARY, SOURCE_REGISTER และ PROJECT_STATUS อัปเดต
- [ ] มี commit แยกตาม Phase และสรุปไฟล์ที่แก้/ผลทดสอบ
